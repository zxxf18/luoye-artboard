# Web 本地部署功能验收

验证日期：2026-09-22

## 环境与方法

- 使用 `docker build -t luoye-artboard:web .` 构建镜像，并用 `docker run --rm -p 18080:8080 luoye-artboard:web` 启动 Nginx 静态站点。
- 通过浏览器打开 `http://127.0.0.1:18080/`，以真实 DOM、按钮操作、IndexedDB 刷新和控制台日志验证；本轮增加 320×360、640×360 和 1280×720 的弹层边界回归。
- 容器健康检查返回 `{"ok":true,"app":"luoye-artboard"}`，页面脚本和素材索引均返回 200，Nginx 配置检查通过。
- 最终镜像的 `playroom.css` 返回 `Cache-Control: no-cache`，响应中包含 `max-width: 860px` 与 `max-width: 640px` 两组窄屏规则；未指纹化的样式不会因长期缓存阻塞后续发布。

## 结论和边界

Web 版的本机能力边界已经明确：下载、IndexedDB、Web Audio 和浏览器文件输入属于纯 Web 能力；背景 MIDI、原生保存位置、桌面窗口尺寸和全屏属于宿主能力。当前网页不会假装这些能力可用，而是禁用并给出提示。

真正发布前还需要在 Chrome/Edge/Safari/Firefox 至少各跑一次旧 `.fly` 和录像文件导入，并补充不同浏览器的下载行为验证。当前 Docker 隔离浏览器已完成 `.luoyex` 和 PNG 上传；Android 端则由 SAF 提供对应的真实文件选择和保存能力。
