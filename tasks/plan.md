# 落叶画板下一阶段路线

## 目标

把现在功能丰富的儿童画板先做成稳定、容易继续创作、可以放心发布的产品，再扩大创作玩法。项目已有 Web、Windows、macOS、Android、iOS 入口，核心风险集中在跨平台回归、复杂作品性能和图层工作流。

## 推荐顺序

### 阶段 1：发布稳定性（优先）

- 增加浏览器端端到端冒烟流程：新画纸、彩虹笔、分形、推拉变形、暗房、保存/打开、PNG 导出。
- 增加大作品性能基准：2K 画布、多背景、多分形、多动画素材、长时间粗笔拖动，记录帧耗时、丢帧和内存。
- 把浏览器冒烟和性能基准接入 CI；保留现有 Node、macOS、Windows 构建检查。
- 每次发布固定生成版本号、构建清单、SHA-256 和变更记录。

验收：关键流程在 Chromium、Windows WebView2 通过；`npm test`、macOS 构建和 Windows 构建都通过；性能基准不会出现长任务持续堆积。

### 阶段 2：图层和作品恢复（最高用户价值）

- 图层重命名、上下移动、复制、隐藏、锁定和缩略图状态更清楚。
- 增加“继续上次作品”和恢复草稿入口，区分自动保存、用户保存和导出文件。
- 为大工程设置可见的内存/图层提示，并让撤销历史在接近预算时可控地收缩。
- 增加旧工程迁移测试和损坏工程的可恢复错误提示。

验收：孩子可以在不丢作品的情况下关闭、重新打开、整理多层作品；撤销、恢复、保存和自动草稿互不覆盖。

### 阶段 3：儿童创作入口

- 首次启动提供三步引导：选背景、选画笔、放入素材。
- 图库增加最近使用、收藏和按主题筛选，减少素材寻找成本。
- 增加少量可直接开始的创作模板，例如涂色页、背景加角色、对称图案。
- 保持现有图示化按钮和大触控区域，所有新入口都补键盘/辅助文本。

验收：新用户能在一分钟内完成一幅简单作品；素材入口不需要记住复杂工具路径。

### 阶段 4：高级创作能力

- 先改进现有选择、变形和一笔成型识别，再考虑新增更多特效。
- 选择工具支持移动、缩放、旋转、复制和多选后的统一操作。
- 形状识别采用“可撤销建议”而非强制替换，避免误识别破坏原画。

验收：识别失败可以保留原笔迹；已有图形和新笔画可以组合识别；操作可撤销且不阻塞画布。

### 阶段 5：多端发布能力

- Windows 安装器、卸载、快捷方式和 WebView2 检查形成发布清单。
- macOS 完成签名、公证和 Apple Developer 配置后再发布正式包。
- iOS/Android 分别验证文件导入导出、触控、后台恢复和音频中断。
- 发布页面提供版本说明、校验值和已知限制。

## 工程约束

- 核心绘制算法继续保持在 `src/core`，界面和平台适配不反向依赖核心之外的实现细节。
- 每个新功能先有一个可复现的端到端场景，再扩展 UI。
- 性能修复必须同时提供基准或回归测试，不能只凭主观流畅度判断。
- 大功能按垂直切片提交，避免一次同时改动画布、图层、平台和素材库。

## 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Canvas 大画布和多层合成耗时增长 | 拖动卡顿、移动端无法使用 | 先建立基准，再做脏区域渲染和缓存；不盲目增加并行层数 |
| 多端行为不一致 | Windows、macOS、移动端出现独有回归 | 共用核心测试，平台层增加最小冒烟流程 |
| 功能继续堆叠 | 儿童找不到入口，维护成本上升 | 优先图层、恢复、引导和素材发现，暂缓同类特效扩张 |
| 工程文件长期兼容压力 | 旧作品无法打开 | 每次 schema 变化都提供迁移和旧工程测试 |

## 建议的第一个开发切片

先做“发布稳定性”里的浏览器冒烟测试和大作品性能基准。它们会直接验证最近修复过的彩虹笔、推拉变形、分形和暗房，也会为后续图层和跨平台发布提供可靠底线。
